2. ЩО ПОКАЗУЮТЬ РЕЗУЛЬТАТИ (коротко)
---------------------------------------------------------------------
 - SelectMany "розгорнув" 3 університети -> 12 факультетів -> 28 кафедр
   в один плоский список (два SelectMany поспіль, по одному на кожен
   рівень вкладеності).
 - Пагінація розбила 12 факультетів на 4 сторінки по 3 (12 / 3 = 4).
   Кількість сторінок = Math.Ceiling(кількість / розмір сторінки).
 - Метод розширення TotalStudents() працює з будь-якою послідовністю
   кафедр: з усіма (4140), з кафедрами одного університету (1640 / 1545 /
   955), одного факультету (750) і навіть після Where (1300).
   Перевірка: 1640 + 1545 + 955 = 4140.


3. ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ
---------------------------------------------------------------------

1) Для чого використовується SelectMany? Чим відрізняється від Select?

   SelectMany проєктує кожен елемент у колекцію і "розгортає" (flatten)
   всі ці колекції в ОДНУ плоску послідовність. Select повертає рівно
   один результат на кожен вхідний елемент; якщо цей результат - колекція,
   то вийде колекція колекцій.

   Приклад із нашої програми:
       universities.Select(u => u.Faculties)
           -> IEnumerable<List<Faculty>>  - 3 елементи (3 списки)
       universities.SelectMany(u => u.Faculties)
           -> IEnumerable<Faculty>        - 12 елементів (один список)

   Для двох рівнів вкладеності SelectMany викликається двічі:
       universities.SelectMany(u => u.Faculties)
                   .SelectMany(f => f.Departments)    // 28 кафедр

2) Як реалізувати пагінацію за допомогою LINQ? Які методи використовуються?

   Двома методами:
     Skip(n)  - пропускає перші n елементів;
     Take(k)  - бере наступні k елементів.
   Формула для сторінки page (нумерація з 1) та розміру pageSize:
       items.Skip((page - 1) * pageSize).Take(pageSize)
   Для 3 факультетів на сторінку: сторінка 1 -> Skip(0).Take(3),
   сторінка 2 -> Skip(3).Take(3), сторінка 3 -> Skip(6).Take(3) тощо.
   Кількість сторінок: (int)Math.Ceiling(count / (double)pageSize).
   Перед пагінацією бажано відсортувати дані (OrderBy), щоб порядок
   елементів на сторінках був стабільним.

3) Поясніть концепцію методів розширення. Як вони інтегруються з LINQ?

   Метод розширення - це статичний метод у статичному класі, у якого
   перший параметр позначений ключовим словом this. Він викликається
   так, ніби є методом самого типу, хоча вихідний код типу не змінювався:
       public static int TotalStudents(this IEnumerable<Department> d) => ...
       allDepartments.TotalStudents();
   Сам LINQ - це набір методів розширення для IEnumerable<T>
   (клас System.Linq.Enumerable: Where, Select, SelectMany, Skip, Take...).
   Тому власні методи розширення для IEnumerable<T> вбудовуються в
   ланцюжок LINQ нарівні зі стандартними:
       allDepartments.Where(d => d.NumStudents > 200).TotalStudents();

4) Приклад власного методу розширення для IEnumerable<T> та його призначення.

   У проєкті є два:
     a) TotalStudents(this IEnumerable<Department> departments)
          => departments.Sum(d => d.NumStudents);
        Призначення: підрахувати загальну кількість студентів у будь-якій
        послідовності кафедр (усі кафедри, кафедри факультету чи
        університету). Бізнес-логіка зібрана в одному місці й не
        дублюється.
     b) GetPage<T>(this IEnumerable<T> source, int pageNumber, int pageSize)
          => source.Skip((pageNumber - 1) * pageSize).Take(pageSize);
        Призначення: універсальна пагінація для будь-якої колекції.
