# Лабораторна робота №13

## Власні винятки та патерн Result

**Варіант:** 7 --- Управління проєктами\
**Сервіс:** `ProjectService`

### Мета роботи

Навчитися створювати власні типи винятків і використовувати узагальнений
патерн `Result<T>` для контрольованої обробки очікуваних помилок без
викидання винятків.

### Завдання за варіантом 7

У роботі розглядається сценарій управління проєктами:

-   власний виняток `ProjectNotFoundException`, який містить
    ідентифікатор проєкту (`ProjectId`);
-   метод `GetProject(int projectId)`, який повертає проєкт або викидає
    `ProjectNotFoundException`, якщо його не знайдено;
-   метод `AssignTask(int projectId, int taskId)`, який повертає
    результат типу `Result<bool>`: успіх у разі призначення завдання або
    невдачу, якщо завдання вже призначено.

### Демонстрація роботи програми

Під час запуску програми в консолі продемонстровано такі сценарії:

1.  Знайдено проєкт з ідентифікатором `1` --- програма виводить його
    дані.
2.  Під час пошуку проєкту з ідентифікатором `99` виникає повідомлення
    про `ProjectNotFoundException`. Це демонструє обробку власного
    винятку.
3.  Завдання `10` успішно призначається проєкту `1`.
4.  Повторне призначення завдання `10` завершується невдачею, оскільки
    воно вже призначене.
5.  Спроба призначити завдання проєкту `99` завершується повідомленням,
    що проєкт не знайдено.
6.  Спроба призначити завдання з недодатним ідентифікатором завершується
    повідомленням про некоректний ID завдання.
7.  Завдання `20` успішно призначається проєкту `2`.

### Висновки

Під час виконання лабораторної роботи було розглянуто два підходи до
обробки помилок у C#.

Власний виняток `ProjectNotFoundException` використовується для
ситуації, коли запитаний проєкт не існує. Така помилка перехоплюється за
допомогою `try-catch`, що дає змогу окремо обробити цей випадок.

Патерн `Result<T>` використовується для очікуваних результатів операції
призначення завдання. За допомогою `IsSuccess` можна визначити, чи
завершилася операція успішно, а через `Error` --- отримати опис причини
невдачі. Це дає змогу повідомляти про звичайні помилки перевірки без
використання винятків.

Отже, власні винятки доцільно застосовувати для ситуацій, коли потрібне
повідомлення про помилку, що перешкоджає виконанню операції, а
`Result<T>` --- для очікуваних сценаріїв невдачі, наприклад повторного
призначення завдання або некоректних вхідних даних. У результаті роботи
було продемонстровано обидва підходи на прикладі управління проєктами.

### Запуск проєкту

У терміналі перейдіть до каталогу проєкту та виконайте:

