// 1. Перший запуск кожного запиту набагато повільніший за середній (наприклад,
//    3,0219 мс проти 0,003306 мс у запиті 1) через JIT-компіляцію та
//    ініціалізацію, тому для порівняння запитів слід брати середній час.
// 2. Найдорожчими виявились запити з Join/GroupJoin (запити 1-3, близько
//    0,0015-0,0033 мс): вони будують хеш-таблицю за ключами і проходять по
//    другій колекції. Пошук максимуму (запит 4) швидший (0,0004-0,0008 мс),
//    бо це один прохід без об'єднання колекцій.
// 3. У запиті 1 синтаксис методів (0,001491 мс) приблизно вдвічі швидший за
//    синтаксис запитів (0,003306 мс), тому що Where виконується до Join і
//    зменшує кількість елементів, які об'єднуються. Порядок операцій
//    важливіший за вибір синтаксису.
// 4. У запитах 2 і 3 обидва синтаксиси дали практично однаковий час, бо
//    компілюються в ті самі виклики методів розширення.
// 5. У запиті 4 orderby + First (0,000446 мс) виявився трохи швидшим за
//    MaxBy (0,000834 мс): у сучасному .NET First() після OrderBy не сортує
//    весь список, а знаходить мінімум за один прохід. Різниця дуже мала і на
//    такій кількості даних лежить у межах похибки вимірювання.
// 6. Відкладене виконання: запит не виконується, доки його не ітерують, тому
//    результати матеріалізуються (ToList, First, MaxBy) усередині виміряного
//    відрізка Stopwatch.
//
// ВІДПОВІДІ НА КОНТРОЛЬНІ ПИТАННЯ
//
// 1) Різниця між синтаксисом запитів і синтаксисом методів. Коли який краще?
//    Синтаксис запитів нагадує SQL:
//        from p in projects where p.StartDate.Year == 2023 select p
//    Синтаксис методів - це ланцюжок викликів методів розширення з лямбдами:
//        projects.Where(p => p.StartDate.Year == 2023)
//    Компілятор перетворює синтаксис запитів на виклики методів, тому
//    швидкодія однакова (це підтвердили вимірювання в запитах 2 і 3).
//    Синтаксис запитів зручніший для складних join, кількох from і змінних
//    через let - код читається майже як SQL. Синтаксис методів зручніший для
//    простих ланцюжків і потрібен для операцій, яких немає в синтаксисі
//    запитів (Count, Sum, MaxBy, Skip, Take, Distinct, ToList тощо). Часто їх
//    комбінують: (from ... select ...).ToList().
//
// 2) Для чого Join і GroupJoin? У чому відмінність?
//    Обидві операції об'єднують дві колекції за збігом ключів.
//    Join - внутрішнє об'єднання (inner join): повертає плоску послідовність
//    пар "елемент першої колекції + відповідний елемент другої". Елементи без
//    пари в результат не потрапляють.
//    GroupJoin - групове об'єднання: для кожного елемента першої колекції
//    повертає його разом з групою (колекцією) усіх відповідних елементів
//    другої. Елементи без пари залишаються з порожньою групою (аналог
//    left join). У нашій роботі: Join (запит 2) показує лише проекти, що мають
//    менеджера, а GroupJoin (запит 3) показує всіх менеджерів, зокрема
//    Roman Hrytsenko з 0 проектів.
//
// 3) Приклади агрегуючих операцій LINQ та їхнє призначення.
//    Агрегація зводить набір значень до одного значення:
//      Count()     - кількість елементів (проектів у менеджера);
//      Sum()       - сума значень (загальна кількість студентів);
//      Average()   - середнє значення (середня ціна);
//      Min() / Max() - найменше / найбільше значення;
//      MinBy / MaxBy - елемент з мінімальним / максимальним значенням ключа
//                      (проект з найдовшою тривалістю);
//      Aggregate() - власна згортка з накопичувачем, напр.
//                    numbers.Aggregate((a, b) => a * b).
//
// 4) Як виміряти продуктивність LINQ-запитів? Які фактори впливають?
//    Вимірювання: клас System.Diagnostics.Stopwatch (Start/Stop,
//    Elapsed.TotalMilliseconds). Щоб замір був коректним, запит треба
//    матеріалізувати (ToList, Count, First) усередині вимірюваного відрізка,
//    зробити прогрів і повторити багато разів та взяти середнє (як у цій
//    роботі: 10 000 повторів); для серйозних тестів існує бібліотека
//    BenchmarkDotNet.
//    Фактори впливу: розмір колекції; складність запиту (join, сортування,
//    групування дорожчі за Where/Select); порядок операцій (фільтр перед join
//    зменшує обсяг даних - див. запит 1); відкладене та негайне виконання
//    (повторна ітерація одного запиту виконує його знову); JIT-компіляція при
//    першому запуску; виділення пам'яті (проміжні колекції, анонімні типи);
//    наявність індексів/хеш-таблиць; тип джерела (список у пам'яті чи база
//    даних через IQueryable).
